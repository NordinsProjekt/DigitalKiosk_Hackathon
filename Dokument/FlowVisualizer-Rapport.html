Flow Visualizer Dashboard

Flow Visualizer är ett realtidsverktyg som visuellt visar hur data rör sig genom systemets alla lager — från det att ett API-anrop når en Controller, genom Service- och Factory-lagren, vidare till Repository och slutligen ner till databasen. Varje metodanrop trackas med exakt tidsåtgång, och resultatet animeras live i en webbläsarbaserad dashboard.

Nyckelpoäng: Visualiseringen kräver inga ändringar i befintlig affärslogik. All instrumentering sker via Decorator-pattern runt existerande interfaces och konfigureras enbart i Dependency Injection-registreringen.

1. Vad är Flow Visualizer?

Flow Visualizer är ett diagnostikverktyg byggt som ett separat Class Library-projekt (FlowVisualizer.Core) integrerat med API-projektets ASP.NET-pipeline. Det består av tre delar:

  1. Tracing-infrastruktur — Decorator-klasser som wrappar varje service, repository och factory med tidsmätning och felhantering.
  2. SignalR Hub — Realtidskommunikation som pushar varje trackat event till anslutna dashboard-klienter via WebSocket.
  3. Webbdashboard — En D3.js-baserad grafvisualisering som ritar noder och animerade linjer i realtid.

2. Arkitekturöversikt

Systemet följer en strikt lagerarkitektur där varje lager kommunicerar nedåt via interfaces. Flow Visualizer lägger sig som ett transparent lager mellan varje interface och dess konkreta implementation:

Controller
ProductsController CustomersController DiscountedProductController
Service
TracingProductService → ProductService | TracingCustomerService → CustomerService
Factory
TracingProductFactory → ProductFactoryAdapter → ProductFactory (statisk)
Repository
TracingProductRepository → ProductRepository | TracingCustomerRepository → CustomerRepository
Database
KioskDbContext + FlowDbCommandInterceptor → SQL Server

Gula chips (Tracing…) markerar de nya Decorator-klasserna. Dessa implementerar samma interface som den inre klassen och delegerar alla anrop vidare, men mäter tid och emitterar ett FlowEvent före och efter varje anrop.

3. Dataflöde — ett konkret exempel

Så här ser ett komplett flöde ut när en klient skapar en ny produkt via POST /api/products:

Controller Products
→
Service ProductService
→
Factory ProductFactory
→
Repository ProductRepository
→
Database SQL Server

Vid varje steg i kedjan genereras ett FlowEvent med följande data:

Fält Beskrivning Exempel
SourceClass Klassen som initierar anropet ProductsController
TargetClass Klassen som tar emot anropet ProductService
SourceMethod Metoden som anropar Add
TargetMethod Metoden som anropas AddAsync
LayerName Vilket arkitekturlager eventet hör till Service
DurationMs Exekveringstid i millisekunder 12.4
IsError Sant om ett exception kastades false
ErrorMessage Felmeddelande (om IsError = true) null
CorrelationId Unikt ID som kopplar ihop alla events i samma HTTP-request a3f7…c9d2

4. Felflöde — röda linjer

Om ett fel kastas (t.ex. ogiltigt produktpris i fabriken) fångas det av Decorator-klassen som sätter IsError = true och ErrorMessage innan eventet emitteras. Felet kastas sedan vidare uppåt i kedjan. I dashboarden syns detta som:

Controller Products
→
Service ProductService
→
Factory — FEL ProductFactory
✕
Repository ProductRepository

Anropet når aldrig Repository-lagret. Den röda linjen och felmeddelandet visas direkt i dashboarden — klicka på linjen för att se det exakta felmeddelandet i en tooltip.

5. Visuella regler i dashboarden

Grön linje — Lyckat anrop utan fel
Röd linje — Exception kastades i anropet
Tunn linje — Lite trafik (få anrop per tidsfönster)
Tjock linje — Mycket trafik (många anrop per tidsfönster)

5.1 Linjetjocklek och tidsfönster

Tjockleken beräknas baserat på antal anrop inom ett konfigurerbart tidsfönster (standard: 10 sekunder). Skalan är linjär från 1.5px (ett anrop) till 8px (flest anrop bland alla kanter). Om inga anrop skett inom tidsfönstret visas en streckad, grå linje.

5.2 Partikelanimation

Varje enskilt anrop visualiseras som en animerad partikel (cirkel) som rör sig längs en Bézier-kurva från käll-noden till mål-noden. Gröna partiklar för lyckade anrop, röda för fel. Animationen tar 600ms.

5.3 Correlation-highlighting

Klicka på en linje för att highlighta hela request-kedjan — alla noder och kanter som hör till samma CorrelationId lyser upp i orange. Klicka på bakgrunden för att avmarkera.

6. Teknisk implementation

6.1 Decorator-pattern

Varje interface i systemet (t.ex. IProductService) wrappas med en Tracing-decorator som implementerar samma interface: 

public class TracingProductService(IProductService inner, FlowTracer tracer) : IProductService
{
    public Task<List<Product>> GetAllAsync()
    {
        return tracer.TraceAsync(
            "ProductsController", "GetAll",       // källa
            "ProductService", "GetAllAsync",      // mål
            "Service",                            // lager
            () => inner.GetAllAsync());           // delegera
    }
    // ... övriga metoder följer samma mönster
}

6.2 FlowTracer

FlowTracer är en scoped service som omsluter varje anrop med en Stopwatch, mäter duration, fångar exceptions och emitterar ett FlowEvent till IFlowEventSink.

6.3 SignalR-pipeline

Events flödar genom systemet enligt: 

Decorator → FlowTracer → IFlowEventSink → SignalRFlowEventSink → FlowHub → Dashboard (WebSocket)

FlowHub exponeras på /flow-hub och broadcastar till alla klienter i gruppen "dashboard". En ring buffer på 1000 events hålls i minnet.

6.4 CorrelationId-middleware

En ASP.NET middleware (CorrelationIdMiddleware) körs först i pipeline och tilldelar ett unikt Guid per HTTP-request via AsyncLocal<Guid>. Alla FlowEvents som genereras inom samma request delar detta ID, vilket gör det möjligt att visualisera hela kedjan som en enhet.

6.5 EF Core Interceptor

FlowDbCommandInterceptor implementerar DbCommandInterceptor och fångar alla SQL-kommandon (SELECT, INSERT, UPDATE, DELETE) som EF Core utför. Varje kommando emitteras som ett FlowEvent med lagret "Database".

7. DI-registrering

All instrumentering konfigureras i Program.cs via decorator-wrapping:

// Registrera tracing-infrastruktur
builder.Services.AddSignalR();
builder.Services.AddSingleton<IFlowEventSink, SignalRFlowEventSink>();
builder.Services.AddScoped<FlowTracer>();

// Wrap repository: Interface → Decorator → Konkret
builder.Services.AddScoped<ProductRepository>();
builder.Services.AddScoped<IProductRepository>(sp =>
    new TracingProductRepository(
        sp.GetRequiredService<ProductRepository>(),
        sp.GetRequiredService<FlowTracer>()));

// Wrap service: Interface → Decorator → Konkret
builder.Services.AddScoped<ProductService>();
builder.Services.AddScoped<IProductService>(sp =>
    new TracingProductService(
        sp.GetRequiredService<ProductService>(),
        sp.GetRequiredService<FlowTracer>()));

9. Designbeslut

Beslut Alternativ Motivering
Decorator-pattern AOP / IL-weaving (PostSharp, Fody) Explicit, debuggbart, inga externa beroenden. Fungerar direkt med befintliga interfaces.
SignalR Polling / Server-Sent Events Native i ASP.NET, bi-directional, lägre latens. Automatisk fallback till SSE/Long Polling.
D3.js Cytoscape.js, kommersiella verktyg Gratis, flexibelt, full kontroll över visuell design. Stort community.
IProductFactory-interface Behålla statisk fabrik Enda sättet att instrumentera statisk klass utan IL-manipulation. Följer Dependency Inversion.
In-memory ring buffer Databaspersistering Noll extra infrastruktur. Dashboarden behöver bara realtidsdata, inte historik.

10. Användning

10.1 Starta

  1. Starta API-projektet som vanligt (dotnet run i DigitalKiosk_Hackathon/).
  2. Öppna dashboard i webbläsaren: https://localhost:{port}/flow-dashboard/index.html
  3. Vänta tills statusen visar Connected.

10.2 Generera trafik

  • Gör API-anrop via Swagger (/), test-api.html, eller valfri HTTP-klient.
  • Varje anrop genererar animerade partiklar och linjer i dashboarden.

10.3 Interaktion

  • Hovra över en linje → tooltip med anropsstatistik (antal, medeltid, felfrekvens).
  • Klicka på en linje → highlighta hela request-kedjan (CorrelationId).
  • Klicka på bakgrunden → avmarkera highlighting.
  • Clear-knappen → nollställ all data.
  • Window-slider → ändra tidsfönster för linjetjockleksberäkning (5–60s).
  • Errors only-checkbox → visa enbart kanter med fel.
Observera: Flow Visualizer är ett utvecklingsverktyg och ska inte vara aktivt i produktion. För att stänga av all instrumentering, byt SignalRFlowEventSink mot NullFlowEventSink i DI-registreringen — detta ger noll overhead.
